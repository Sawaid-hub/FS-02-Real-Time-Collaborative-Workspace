## Initial working assumptions

- Start with collaborative rich text pages; a freeform Figma-style canvas is outside the MVP.
- Validate concurrent editing and persistence before interface polish.
- Architecture and directory layout in `Overview.md` are proposals until checked against any starter code or mentor guidance.

## Decisions to record

- Standards source: `RULES.md` (human-readable); `.cursor/rules/*.mdc` for the agent
- Authentication approach: Auth.js v5 credentials (email/password, bcrypt). JWT sessions so the collab server can verify a minted collab token with `AUTH_SECRET` (`jose`), without sharing a session table.
- Yjs provider/server and room naming: TipTap + `@tiptap/extension-collaboration`. Separate Node `y-websocket`-protocol server in `server/collab`. Rooms: `page:{pageId}` via `roomNameForPage`.
- Document persistence/update strategy: collab server loads/saves `Page.yDoc` as `Y.encodeStateAsUpdate` bytes, debounced. Awareness is ephemeral.
- Snapshot/version format: `BYTEA` Yjs update plus optional `previewHtml`. Inspect-only (no restore into a live room).
- Redis coordination approach: pub/sub of Yjs updates (and awareness) between collab processes. Postgres remains source of truth.
- Hosting/deployment: local Docker Compose for Postgres + Redis; Next `:3000`; collab `:1234` (second instance `:1235` for multi-instance tests). Demo via local run + recording if cloud WebSockets are not available.
